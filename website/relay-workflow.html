从 Claude Code 切到 Codex / Cursor：跨 Agent 对话接力实战流程

遇到限流或想换用另一款编程助手处理测试、重构与收尾时，手工复制半截聊天记录往往漏掉报错栈与否决过的方案。本页拆解 Senrelay（续境，GitHub 仓库 qingsongcui/ContextCore）如何用短简介选号、分页原文压缩与待命保护（must_not_execute）在已接入的核心宿主间传递对话上下文。

核对日期：2026-11-15 适用范围：六大核心宿主（macOS Apple Silicon） 免费开源：$0 · MIT License · 免登录
接力过程的三道保险

先列短简介，不一次爆窗/contextcore 先列出简短编号、时间、工作区与摘要，只在选定目标会话后再拉取全文。

按完整原文分页压缩新宿主通过 read_conversation_messages 分页读完真实用户指令与助手回复并原地压缩，不靠提前生成的粗糙摘要凑数。

只报序号默认待命如果回复只有编号、没有额外执行要求，新助手触发 must_not_execute=true：汇总进度与阻塞后停住，等确认再改代码。

01 · SIX-STEP RELAY PROTOCOL

六步接力协议：一条旧对话如何在新宿主里无缝续上

历史参考验收覆盖四个真实宿主（Codex CLI、Oh My Pi CLI、Antigravity Desktop、OpenCode）。Cursor Desktop 与 Claude Code 的续做停在协议验证。六个宿主的记忆写入均只有合成测试，当前版本与本机环境需分别核验。 历史验收明细

当 Claude Code 排查到一半遇到配额限制、或者你想换到 Codex CLI / Cursor / OpenCode 继续改源码时，无需打开浏览器手工导出 Markdown。只要本机常驻服务运行在 127.0.0.1:8420 且双端均已接入 http://127.0.0.1:8420/mcp/（键名 contextcore，配置路径见15 宿主配置路径指南），接力按以下六步执行：

  1. 在原宿主正常对话：Senrelay 对六大核心宿主（Claude Code、Codex、Cursor、Antigravity、Oh My Pi、OpenCode）可索引已接入宿主的本地对话，并由伴生工具记录 working_tasks 与带原话出处的项目记忆。
  2. 在新宿主触发接力：打开 Codex CLI、Cursor 或 Oh My Pi，输入 /contextcore，或直接说「继续刚才的对话 / 接力」。
  3. 短简介选号认会话：新助手调用 list_relay_conversations 返回编号列表，展示项目目录、所属 Git Worktree 分支、时间与短简介。
  4. 分页读完完整原文并压缩：选定会话编号后，工具按固定分片顺序调用 read_conversation_messages，读尽多轮需求澄清、失败排查与工具结果边界，直接由当前模型消化压缩。
  5. Worktree 与路径消歧：若同一个仓库开启了多个 git worktree 并行开发，索引按实际 worktree 根路径分开归档，避免把分支 A 的上下文误塞进分支 B。
  6. 受控交接进入下一步：新助手结合当前目录差异、working_tasks 状态与前置约束（如 AGENTS.md 规则），按你的回复模式决定“汇报待命”或“立刻继续执行”。
02 · STAND-BY VS EXECUTION

两种回复模式：为什么只发数字不会乱改文件

很多人不敢用跨工具上下文接力的顾虑在于：“新模型读完记录直接动手改错方向怎么办？”Senrelay 的伴生指令对回复意图做了严格区分：

模式 A · 仅输入序号（must_not_execute=true）

当你只回复 1 或 #2 时，relay_conversation 会附上 must_not_execute=true 约束。新助手读完全文与当前工作区差异后，只汇报“目前改到哪一步、刚试错失败的路径、当前待确认风险”，随后停在输入栏等待拍板，绝不擅自写入文件或执行命令。

模式 B · 编号 + 明确下一步指令

当你明确输入 接 1 号会话，直接把失败的单测修通并运行检查 时，新助手在加载全文与工作任务后立即沿着既有约束继续修改文件与验证。

终端交互示例

# Step 1 · 在 Codex CLI 或 Cursor 对话框唤醒列表
你：/contextcore

# Codex 返回简短候选列表（仅占极少 Token）
[1] Claude Code · 14 分钟前 · ~/work/payment-service (worktree: fix-webhook)
    排查 Stripe webhook 幂等键竞态，单元测试尚余 1 个超时用例
[2] Cursor · 2 小时前 · ~/work/payment-service (worktree: main)
    整理计费对账表索引迁移 SQL

# Step 2A · 只回复编号 → 读取全文后汇报现状并待命，不动工作区文件
你：1

# Step 2B · 也可直接附带指令 → 载入全文后继续执行目标任务
你：1，请先运行 pytest -k webhook 看最新报错再提出修改计划

Claude Code 额度用完，切到 Codex 前先核对什么？

  1. 先核对项目目录和分支。在新窗口确认当前工作目录；如果同一仓库有多个工作树，用 git status --short --branch 核对分支和现有改动，再从候选列表按目录、时间和任务选会话。
  2. 先只回编号，做一次只读交接。让接收方汇报已经做了什么、哪一步卡住、哪些结论还没验证。若汇报与实际文件或测试状态不符，先核对来源会话和原文是否读完。
  3. 给出一个明确的续做任务。例如「只运行刚才失败的测试，给我最新报错」。接收方以当前工作树和新测试结果为准，区分旧记录和本次执行结果。

05 · WORKFLOW FAQ

跨 Agent 接力常见问题

为什么 Codex 或 Cursor 只读到了 Claude Code 对话的最后几条？+

选中会话后，先看返回的消息数。如果原文只加载了一部分，让接手的助手从 offset=0 调用 read_conversation_messages，逐页跟随返回的 next_offset，直到它为 null。每页实际返回的条数可能少于请求值。可以让助手先报出读完的消息总数，再总结。如果每次都停在预览，检查接收端安装的 ContextCore Skill 或命令是否为新版。

为什么接力要分页读原始对话，而不是预先生成一段“AI 摘要”？+

预先压缩往往丢失具体的报错行号、已经验证过不通的方案和工具调用结果。通过 read_conversation_messages 分页按原文顺序加载再由接盘助手当场理解，可以把细节损耗降到最低，同时靠短简介先列表避免无谓浪费上下文窗口。

同一项目开着两个 git worktree，接力会不会把分支搞混？+

不会。会话索引按各自独立的 Worktree 路径与分支信息区分归档，列表短简介和接力工具会明确显示路径归属，不会将分支 A 的修改记录混入分支 B。

只接力对话，不连接配置管理器和记忆台账可以吗？+

可以按需独立开启权限：读取会话、改写宿主配置与下载可选本地模型各自确认、互不捆绑。不过开启 working_tasks 与项目记忆能帮助接盘模型更快认清尚未完成的目标与前置规则。

Windows 或 Linux 用户如何做跨助手交接？+

Senrelay 当前仅支持 Apple Silicon macOS（$0 MIT 开源），暂不支持 Windows 与 Linux。跨平台工作流建议将核心约定写入仓库根目录 AGENTS.md，在切换客户端前让原助手整理一份简明 HANDOFF.md，或参考我们的5 种方案对比。

6-Step Cross-Agent Relay Flow

Memory writes have synthetic test coverage across all six. Check the current release and your installation separately. Historical verification details

When Claude Code hits a usage cap mid-debug—or you prefer Codex CLI, Cursor, or OpenCode for final test verification—keep both clients pointed at local loopback http://127.0.0.1:8420/mcp/ under MCP key contextcore (see Verified Config Paths Across 15 Agents):

  1. Work Normally in Host A: Senrelay can index local transcripts in the connected core hosts (Claude Code, Codex, Cursor, Antigravity, Oh My Pi, OpenCode) while tracking working_tasks and source-linked memories.
  2. Invoke Relay in Host B: Open Codex, Cursor, Oh My Pi, or OpenCode and enter /contextcore (or say "Relay").
  3. Pick From Short Briefs: list_relay_conversations returns numbered sessions with project path, Git worktree branch, recency, and concise summary.
  4. Page Complete Transcript Turns: Once selected, read_conversation_messages iterates page by page through complete original messages and tool results so the new model compacts live truth directly.
  5. Disambiguate Git Worktrees: Sessions stay partitioned by exact worktree path so concurrent branches inside one repository never bleed into each other.
  6. Controlled Hand-Over: Combining workspace diffs, active working_tasks, and pinned constraints, Host B waits for approval on number-only replies or proceeds when a task accompanies your choice.
02 · STAND-BY VS EXECUTION

Why Replying With a Number Won't Touch Files Yet

Developers hesitate to hand active edits to a second model when they worry it will rush ahead and break files. Senrelay separates inspection from execution via two explicit reply modes:

Mode A · Number-Only Selection (must_not_execute=true)

Sending just 1 passes must_not_execute=true to relay_conversation. The receiving client summarizes verified changes, failed hypotheses, and pending steps, then pauses cleanly without editing files or running destructive shell commands.

Mode B · Number + Action Instruction

Sending 1 - fix the failing webhook test and run pytest tells the receiving agent to load full context plus working_tasks and immediately pick up execution.

Sample Terminal Sequence

# Step 1 · Trigger short-brief listing inside Codex CLI or Cursor
You: /contextcore

# Compact numbered list keeps initial token cost tiny
[1] Claude Code · 14m ago · ~/work/payment-service (worktree: fix-webhook)
    Debugging Stripe webhook idempotency race; 1 timeout test left
[2] Cursor · 2h ago · ~/work/payment-service (worktree: main)
    Drafting billing reconciliation index migration SQL

# Step 2A · Number only -> inspects transcript, reports status, stands by
You: 1

# Step 2B · Number + explicit task -> continues editing and verifying
You: 1, run pytest -k webhook first and propose the minimal fix

05 · WORKFLOW FAQ

Relay Workflow FAQ

Why did Codex or Cursor load only the last few messages from Claude Code?+

After you select a conversation, check the returned message count. If the transcript is partial, ask the receiving agent to read from offset=0 with read_conversation_messages and follow each returned next_offset until it is null. A page can contain fewer messages than requested. Ask the agent to report how many messages it read before summarizing. If it repeatedly stops at the preview, check that the receiving host has the current ContextCore skill or command installed.

Why page original transcripts instead of pre-summarizing every turn?+

Background summaries routinely strip exact error lines, file diffs, and failed hypotheses. Reading bounded pages of raw turns via read_conversation_messages lets the receiving model compress details tailored to its next task.

How does relay avoid mixing parallel git worktrees in the same repository?+

Sessions stay indexed by exact working directory and worktree path. Both short-brief listings and relay tool inputs surface the worktree path explicitly before loading turns.

Can I use /contextcore relay without letting Senrelay write all host configs?+

Yes—session reading, host file modifications, and local model downloads ask for separate confirmations. Pairing relay with working_tasks and source-linked memories keeps long tasks organized, but remains opt-in.

What should Windows or Linux developers use instead of Senrelay?+

Senrelay is currently $0 MIT open source for Apple Silicon macOS only. Cross-platform teams should use Git-tracked AGENTS.md plus a short HANDOFF.md generated before switching agents, or review all 5 options in our comparison guide.
