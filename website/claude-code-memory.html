Claude Code 记忆与上下文管理指南 — Senrelay 续境

了解 Claude Code 记忆、项目规则与对话上下文的区别，并通过 Senrelay 在 Codex 或 Cursor 中接着处理已有任务。

更新于 2026-11-25 · Senrelay 维护者

Claude Code 记忆、规则文件和对话上下文各做什么？

项目规则记录编码约定和工作要求，对话原文记录具体报错、尝试与决策，工作记忆记录当前任务状态和可复用经验。理解当前问题通常需要同时参考这些资料。Senrelay 在本机保存可追溯来源的记忆，使用时可以回到原始记录核对。

Claude Code 自身的记忆与规则用法见 Claude Code 官方记忆文档。Senrelay 的跨助手接力还需目标助手接入本机服务。

Claude Code 的记忆存在哪里？

Claude Code 每次会话都从空白的上下文窗口开始。跨会话保留下来的知识来自两类文件：你自己写的 CLAUDE.md，以及 Claude 自己记下的自动记忆。

  • ~/.claude/CLAUDE.md：个人指令，对所有项目生效。
  • ./CLAUDE.md 或 ./.claude/CLAUDE.md：团队共享的项目指令；仓库里的 AGENTS.md 也可以承担这个角色。
  • ./CLAUDE.local.md：只对你自己、只对当前项目生效的个人指令，应加入 .gitignore。
  • .claude/rules/*.md：按主题拆分的规则文件，可以限定只对某些文件路径生效。
  • ~/.claude/projects/<project>/memory/：自动记忆目录，包含一个 MEMORY.md 索引和每条记忆一个文件；会话开始时加载 MEMORY.md 的前 200 行或 25KB。

启动时，Claude Code 会加载工作目录及其所有上级目录中的 CLAUDE.md；子目录里的 CLAUDE.md 在 Claude 处理该目录下的文件时才加载。CLAUDE.md 可以用 @path/to/file 引入其他文件，最多嵌套四层。用 /init 可以生成项目 CLAUDE.md 的初稿，用 /memory 可以查看已加载的文件并浏览自动记忆。每个 CLAUDE.md 建议控制在 200 行以内。

这些文件描述的是“怎么工作”，并不保存对话本身：遇到过的报错、试过的方案、停在哪一步，都留在会话原文里。从 Claude Code 切到 Codex 或 Cursor 时，新助手看不到的正是这部分，也正是 Senrelay 负责接力的内容。

从 Claude Code 切到 Codex 或 Cursor 继续任务

  1. 在 Apple Silicon Mac 上按 安装指南启动 Senrelay，并接入来源和目标助手。
  2. 在目标助手输入 /contextcore，按标题与简介选择原对话。
  3. 只回复序号时，目标助手读取原文并整理前情，然后等待下一条任务指令。选场时同时说明具体任务，则按该指令继续。
  4. 核对原对话中的文件路径、已完成工作、限制与下一步，再让目标助手继续。具体示例见 Claude Code 转 Codex 接力流程。

本地记忆与接力的适用范围

当前桌面版面向 macOS 14.0+ Apple Silicon。Claude Code、Codex、Cursor 等六类核心宿主支持会话接力，其余扩展宿主的配置能力见 MCP 配置与宿主支持表。原文分页读取后会在接收助手的上下文窗口内压缩，仍受该助手的窗口和工具权限约束。接力结果需要检查。

常见问题

配置 MCP 就会自动同步全部对话吗？

MCP 配置建立工具连接。会话接力还需要已接入的来源记录、目标助手的伴生指引与明确的接力指令。日常共享记忆按授权采集和使用。

Senrelay 能扩展 Claude Code 的上下文窗口吗？

上下文窗口由助手和模型决定。Senrelay 负责组织历史、来源和任务状态，接收助手读取后在自己的窗口内整理。

What do Claude Code memory, instructions, and conversation context contain?

Project instructions describe coding conventions and working rules. Transcripts preserve errors, attempts, and decisions. Working memory records task state and reusable lessons. Senrelay keeps source-linked memories locally so an agent can check the original record when it needs more context.

See the official Claude Code memory documentation for its own memory and instruction features. Cross-agent continuation with Senrelay also requires connecting the receiving assistant to the local service.

Where does Claude Code store memory?

Claude Code starts every session with a fresh context window. Two kinds of files carry knowledge between sessions: CLAUDE.md files that you write, and auto memory that Claude writes for itself.

  • ~/.claude/CLAUDE.md: personal instructions for every project.
  • ./CLAUDE.md or ./.claude/CLAUDE.md: team instructions shared with the project. A repository's AGENTS.md can serve the same role.
  • ./CLAUDE.local.md: personal instructions for one project. Add it to .gitignore.
  • .claude/rules/*.md: rule files split by topic, optionally scoped to specific file paths.
  • ~/.claude/projects/<project>/memory/: auto memory, with a MEMORY.md index and one file per memory. The first 200 lines or 25KB of MEMORY.md load at the start of a session.

At launch, Claude Code loads CLAUDE.md files from the working directory and every directory above it. A CLAUDE.md in a subdirectory loads when Claude works with files in that directory. A CLAUDE.md can pull in other files with @path/to/file, up to four hops deep. Run /init to draft a project CLAUDE.md, and /memory to see which files are loaded and to browse auto memory. Keep each CLAUDE.md under about 200 lines.

These files describe how to work. They do not hold the conversation itself: the errors you hit, what you tried and where you stopped stay in the session transcript. That is what another assistant cannot see when you switch from Claude Code to Codex or Cursor, and it is what Senrelay relays.

Continue Claude Code work in Codex or Cursor

  1. Follow the installation guide on an Apple Silicon Mac and connect the source and receiving assistants.
  2. Enter /contextcore in the receiving assistant and identify the old conversation by its title and brief.
  3. A number-only selection loads and compacts the transcript, then waits for the next task instruction. Include a concrete task with the selection to continue directly.
  4. Check file paths, completed work, constraints, and next steps against the original conversation. Follow the Claude Code to Codex relay walkthrough.

Common questions

Does adding MCP automatically sync every conversation?

MCP configuration connects tools. Conversation relay also needs an available source record, companion instructions in the receiving assistant, and an explicit relay request. Everyday shared memory follows authorized collection and use.

Does Senrelay increase the Claude Code context window?

The assistant and model determine the context window. Senrelay organizes history, sources, and task state for the receiving agent to read and compact within its own window.
