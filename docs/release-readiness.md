# Release readiness: implementation, gaps and evidence

Requirements: [public specification](SPECIFICATION.md). Verification summary and historical observations: [evidence register](evidence.md). Operational commands: [application guide](../app/README.md).

**Current status: `1.0.0-beta.2` Public Beta candidate (Apple Silicon `arm64`, macOS 14.0+, ad-hoc signed, build 2).** Automated gates pass across 1,648 backend tests (+ 1 opt-in 100k benchmark via `SENRELAY_USAGE_PERF=1`), 205 frontend Vitest tests, 1,518 bilingual UI keys, 29 `scripts/tests`, website static/brand/i18n/interaction/sphere checks, installed-wheel 11-resource verification (`check_release_readiness.py`), native `Senrelay.app` / `Senrelay-macOS.zip` bundle/archive/hook/lifecycle/WKWebView checks, and repository security scanning (`verify_repository_security.py`). External account/OAuth/billing validation, live host reload across all surfaces, optional local semantic model downloads, and clean-Mac physical Gatekeeper/upgrade/reboot acceptance remain distinct boundaries documented below.

## Approved Beta scope

The first public release is an ad-hoc signed, unnotarized Apple Silicon Beta. Developer ID, notarization, Intel and billing are outside this release gate; functionality, data safety, host compatibility and clean-system installation remain mandatory.

## Evidence rules

- Historical baseline checks do not validate the current shared checkout; a passing source suite does not validate an installed wheel.
- Bundled host grades describe a reference testbed. A new installation starts unverified until its own observations exist.
- Keep parser/configuration/protocol/host consumption/model effect/daemon deployment evidence separate, including Desktop versus CLI surfaces.
- An unsupported feature is a delivery gap, not an external authorization prerequisite. Optional semantics/relations are first-release scope, not deferred scope. No full multi-host configuration replacement claim is justified by the subset below.
- Preserve private raw transcripts and execution attachments outside public artifacts. Public summaries are not raw evidence links.

## Release verification checklist

Run the full verification suite in [CONTRIBUTING](../CONTRIBUTING.md), plus `python3 -m unittest discover -s scripts/tests -v`, `app/scripts/check_release_readiness.py`, `app/macos/verify_bundle.py`, `app/macos/verify_archive.py`, `app/macos/verify_hook_distribution.py`, `app/macos/verify_data_lifecycle.py`, `app/macos/verify_native.py`, and `scripts/verify_repository_security.py`. Scope gaps and external prerequisites above remain visible alongside passing automated checks. No production LaunchAgent change, host modification, real account login, paid model call/download, or public release is triggered automatically by running verification scripts.
